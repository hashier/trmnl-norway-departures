Framework 3.4.4: the "And N more" label hides itself

Summary. With data-overflow-max-cols and data-overflow-counter="true", the overflow counter disappears on 3.4.4 when the last column comes out exactly full while rows are still hidden. The label stays in the DOM with display: none. 2.3.7 shows the label for the same markup.

Cause. In enforceRealColumnsFit() (js/3.4.4/plugins.js, around line 1720) the label is appended to the last column. If it does not fit, the loop hides the last .item of that column. The label is itself a <div class="item"> and sits at the bottom, so it is picked first and hides itself; the column then fits and the loop stops. Its number can also be one too high, because countHiddenOverflowItems() now counts the hidden label. 2.3.7's matching loop leaves the label out of the candidates (filter(t => t !== label && ...)).

Suggested fix: leave the label out of the candidates, as 2.3.7 did.

-      const candidates = Array.from(lastCol.children).filter((c) => c.classList && (c.classList.contains('label') || c.classList.contains('item')) && c.style.display !== 'none');
+      const candidates = Array.from(lastCol.children).filter((c) => c !== label && c.classList && (c.classList.contains('label') || c.classList.contains('item')) && c.style.display !== 'none');

Reproduction

Both frames load the same markup, a half vertical view of a departure board (the Ruter / Entur Norway recipe) with fixed data, on a 1-bit OG screen. Only the framework version differs. Below each frame is what the page reports after TRMNL_PLUGINS_READY. The exact layout depends on the browser's text metrics, so the frame at its natural height may or may not hit the case. The page therefore also renders the same markup in a fresh hidden frame for each data-overflow-max-height from 300 to 420 px (in 4 px steps) and lists the heights where rows are hidden but no counter is visible.

Tested in Firefox 159 on macOS.
